# 기획서

독자가 목표·가정·요구사항·결정 상태를 구분할 수 있어야 한다.

- `응답 시간을 줄이는 것을 목표로 한다`의 목표를 `응답 시간을 줄인다`라는 성과로 바꾸지 않는다. 제안·검토·합의·확정도 구분한다.
- `개선 방안에 대한 검토의 진행이 필요하다` → `개선 방안을 검토해야 한다`처럼 동작을 푼다. 담당자·기한·수치가 없으면 교정 과정에서 채우지 않는다.
- 정의와 행동 지침이 섞여 경계가 흐리면 나눈다. `보관 기간은 로그를 저장하는 기간이며 관리자는 이를 30일로 설정해야 한다`에서 뜻·관리자·30일·의무를 보존한다.
- 표의 `담당`, `완료 조건`, `검토 상태` 같은 명사형은 유지한다. 본문의 모호한 명사 쌓기와 구분한다.
- `설정 파일을 심볼릭 링크로 연결합니다`가 확정된 구현 요구사항이면 보존한다. 사용자 가치 설명이 필요해도 근거 없는 효과를 덧붙이지 않는다.

위 예시는 판단을 설명하기 위해 만든 문장이다. 실제 용례를 인용한 자료로 취급하지 않는다.
