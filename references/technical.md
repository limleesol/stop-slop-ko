# 기술 문서

독자가 시스템을 이해하거나 조작할 수 있어야 한다. 작동 방식과 제한 조건을 보존한다.

- 정의문과 정확한 기술 용어는 필요한 내용이다. `캐시는 응답을 임시 저장하는 공간이다`를 정의형이라는 이유만으로 고치지 않는다.
- 무생물 주어라도 실제 동작이면 유지한다. `서버는 요청을 처리한다`는 정상이다. `서버는 사용자 경험을 약속한다`처럼 추상적 평가를 붙였다면 원문에 있는 동작으로 쓴다.
- 명사와 피동 표현이 겹쳐 동작이 흐려지면 푼다. `요청에 대한 처리의 수행이 이루어진다` → `요청을 처리한다`. 처리 주체가 원문에 없으면 새로 지정하지 않는다.
- `설정 파일을 심볼릭 링크로 연결합니다`처럼 작동 방식을 설명하는 문장은 유지한다. 효과만 남기면 설치·운영에 필요한 설명이 사라진다.
- 원인·조건·실행 순서와 필수·선택 구분을 보존한다. 독자가 모르는 용어는 주어진 설명으로 풀고 식별자는 유지한다.

위 예시는 판단을 설명하기 위해 만든 문장이다. 실제 용례를 인용한 자료로 취급하지 않는다.
